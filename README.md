# Meteor Paper Analyzer

一个面向**非细分领域专家**的学术论文深度分析 Skill。

它将论文阅读整理成固定的 **Q1–Q7** 结构，不只回答“论文讲了什么”，还会解释必要的前置概念、还原算法工作流、核对实验设置与数字，并用一个具体案例把算法从输入到输出完整跑一遍。

## 核心特性

- **默认面向非领域专家**：不假设读者已经理解论文所在子领域的术语。
- **术语先解释再使用**：例如 FFN neuron、Neuron Mining、PPR、contrastive decoding、memory token 等概念，第一次出现时会先说明直觉、技术含义和在本文中的作用。
- **阅读完整论文**：要求覆盖摘要、引言、相关工作、方法、实验、结论/局限，以及必要的附录、表格、图和案例，而不是只根据 abstract 总结。
- **保留技术细节**：重要公式、损失函数、模型结构、训练/推理流程、数据集、baseline、metric、模型规模和关键实验数字都会尽量保留。
- **避免实验数字误读**：明确区分 Recall@k、F1、Accuracy，以及绝对提升和相对提升。
- **区分论文事实与分析扩展**：不会把模型自行提出的未来方向、教学示例或示意数值伪装成论文原文结论。
- **固定 Q7 算法示例**：优先使用论文正文/附录中的真实案例；若论文没有，则严格依据真实架构构造一组明确标注的教学示例。
- **默认简体中文输出**：关键英文术语会在首次出现时保留原文，便于继续查阅论文。

## 输出结构

Skill 默认按照下面七个问题输出：

1. **Q1：这篇论文试图解决什么问题？**
2. **Q2：有哪些相关研究？**
3. **Q3：论文如何解决这个问题？**
4. **Q4：论文做了哪些实验？**
5. **Q5：有什么可以进一步探索的点？**
6. **Q6：总结一下论文的主要内容**
7. **Q7：用一个具体例子展示算法是怎么工作的**

其中 Q7 会尽量展示：

```text
原始输入
   ↓
预处理 / 表示
   ↓
核心模块 1
   ↓
中间结果
   ↓
核心模块 2
   ↓
打分 / 筛选 / 检索 / 推理
   ↓
最终输出
```

如果论文存在适合的 worked example、case study 或 appendix example，会优先使用论文自己的案例；否则会创建一个**明确标注为教学示例**的输入输出流程。

## 安装

### 方法 1：直接安装打包版本

仓库根目录提供 `skill.zip`。

在支持 Skills 的 ChatGPT 中打开 Skill 管理页面（`/skills`），上传 `skill.zip` 即可。

### 方法 2：查看 / 修改源码

Skill 源码位于：

```text
meteor-paper-analyzer/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── analysis-template.md
    ├── explanation-guide.md
    └── quality-rubric.md
```

修改后重新打包整个 `meteor-paper-analyzer` 目录即可。

## 使用方式

上传论文 PDF 或提供可访问的论文链接，然后直接提出例如：

```text
使用 Meteor Paper Analyzer 帮我分析这篇论文。
```

也可以指定关注点：

```text
按 Meteor Paper Analyzer 的 Q1-Q7 模板分析这篇论文，尤其把方法和消融实验讲清楚。
```

```text
分析这篇论文。我不是这个细分领域的研究者，专业概念第一次出现时先解释清楚。
```

## 设计原则

### 1. 不把术语当作解释

一个术语如果是理解后续内容的前置条件，就必须先建立概念桥梁。

例如不能直接写：

> 前人通过 Neuron Mining 定位 FFN neurons……

而应先解释：

- Transformer 中 FFN 大概是什么；
- 在这个语境下为什么会把 FFN 的某些隐藏维度称为 neuron；
- Neuron Mining 想从这些 neuron 中找什么；
- 然后再进入论文与前人工作的差异。

### 2. 论文事实和教学解释分开

如果 Q7 使用自构案例，会明确写明：

> **下面是依据论文真实架构构造的教学示例，并非论文中的真实实验样本；其中具体文本/数值仅用于说明流程。**

任何人为设置的分数、概率、激活值等都必须标注为**示意数值**，不能伪装成论文实验结果。

### 3. 技术深度不等于堆术语

目标不是把论文里的术语重新排列一遍，而是让读者最终能够理解：

- 为什么要做这项工作；
- 前人的方法到底在做什么；
- 新方法每个模块输入输出是什么；
- 实验为什么能支持作者的主张；
- 一个具体样本经过算法时实际发生了什么。

## 适合的论文类型

最初主要面向 AI / ML / NLP / RAG / LLM 等计算机方向论文设计，但模板本身也可以用于其他包含明确方法、实验与算法流程的研究论文。

## 文件说明

- `SKILL.md`：Skill 主执行逻辑与行为约束。
- `references/analysis-template.md`：Q1–Q7 的详细输出模板。
- `references/explanation-guide.md`：面向非领域专家的概念解释规范。
- `references/quality-rubric.md`：事实、数字、实验和分析质量检查清单。
- `skill.zip`：可直接上传安装的完整 Skill 包。

## 状态

当前版本已经包含：

- Q1–Q7 固定分析范式；
- 面向非细分领域专家的术语解释机制；
- 论文案例优先 / 教学案例兜底的 Q7 工作流；
- 实验数字和绝对/相对提升校验；
- 对未来研究方向的约束，避免泛泛而谈。

后续可以继续根据真实论文使用效果迭代。
